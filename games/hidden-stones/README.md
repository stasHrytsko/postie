# Hidden Stones (Камни под листами)

- **Статус:** в игре; перенесена из stazzi `apps/casual/hidden-stones` целиком (2026-11-13). В stazzi — прототип одним файлом `index.html`, Gate 1 `approved` (2026-11-09), на витрине в Ready с 2026-11-10; спеки нет.
- **Источник правил:** stazzi `index.html` (функции `trace`, `shoot`, `tapCell`, `check`) и `tools/hidden-stones-solver.mjs`; история решений — `IDEA.md` в этой папке (копия stazzi). Разделы 2–8 IDEA.md описывают отклонённый автором «перевёрнутый» вариант; действует раздел «Прототип».

## Правила
Black Box (Эрик Соломон): в поле `n × n` (5×5 или 6×6) спрятаны `k` камней.
- **Тап по краю** — выстрел лучом внутрь. Виден только результат на краях: **✕** — луч поглощён камнем; **↩** — луч вернулся туда, откуда вошёл; **одинаковое число** на двух краях — вошёл в одном, вышел в другом. Повторный тап по уже стрелявшему краю бесплатный, только подсвечивает пару.
- Луч: камень прямо впереди — поглощение; камень по диагонали впереди — поворот на 90° прочь от него; два по обеим диагоналям — разворот; если поворот нужен ещё на краю, до входа — отражение.
- **Тап по клетке** — отметить / снять камень (не больше `k` отметок). **Check** — при `k` отметках: верно — победа; нет — «Not yet: m of k are right», ничего не стоит.
- **Перетаскивание** по клеткам и краям — карандаш: игрок сам рисует, где, по его мнению, прошёл луч (путь луча игра не показывает — решение автора 2026-11-09). Назад по линии — стирает последний шаг. Кнопки «Undo line» и «Erase lines».
- Поражения нет. Счёт — число выстрелов (меньше — лучше).

## Экран
Поле с рамкой из портов: пустой порт — стрелка внутрь (Mut); результат — кружок: ✕ на Apricot, ↩ на Blue, число на Sage (у каждого свой знак, цвет не единственный канал); последний выстрел и его выход обведены. Отметка — кружок с «?» и ободком Ink; после победы камни — сплошные Ink. Под полем — легенда трёх результатов. Счётчики «Shots» и «Stones m / k».

## Уровни и сложность
**15 уровней** — все уровни stazzi (`tools/hidden-stones-levels.json`, генератор `tools/hidden-stones-solver.mjs`), в том же порядке. У каждого расстановка единственная по результатам всех лучей.

`solution` = `{ shots, marks }`: `marks` — камни; `shots` — короткий набор выстрелов, после которого подходит ровно одна расстановка из `k` камней (найден жадно скриптом `tools/shots.js`: каждый следующий выстрел сильнее всего режет оставшиеся варианты). Это доказательство, что уровень решается дедукцией, а не перебором. `best` нет: в stazzi оптимального числа выстрелов нет, а жадный набор не доказанно минимальный (1–14 выстрелов).

Сложность (`difficulty`) — по числу камней: 1–2 → 1 (уровни 1–5), 3–4 → 2 (6–12), 5 → 3 (13–15). С этим согласуется и длина жадного набора выстрелов (у 13–15 — 10–14).

## Отличия от stazzi
- Движок — чистый JS (`engine.js`), функция луча скопирована из солвера stazzi; совпадение проверено на 440 000 случайных лучей.
- Уровни без замков (в stazzi следующий открывался после прохождения), «лучший результат» по уровню не хранится.
- Нет «Как играть» с картинками и руки на уровне 1 — текст правил оболочки и легенда под полем.
- Добавлена кнопка «Undo line» (в stazzi только «Erase» всех линий).
- Карандаш — пунктир цвета Mut (в stazzi — умбра, такого токена в Postie нет).

## Открытые вопросы
- Нужен ли `best` (минимум выстрелов): точный минимум — перебор по наборам портов, жадный набор не гарантирует оптимум.
- Спеки в stazzi нет; правила сняты с прототипа — подтвердить у автора, что Postie берёт их как есть.
- Правила длинные для текста в оболочке — нужен «Как играть» с картинками.
