# Parcels (Посылки) — вместе с Pair Up

- **Статус:** в MVP, ядро (дедукция). **Слита с Pair Up 2026-11-19 (решение автора):** база — Parcels (рамка → посылка уходит → всё сверху падает), правило пар из Pair Up живёт в ней как кубики с точками. Папка Pair Up — `archive/games/pair-up/`. Бывший вид правил Cave In (камни, пустые клетки, уровень 31) убран: в одно правило не входит; история — `IDEA-cave-in.md`.
- **Источник:** цифры — stazzi `apps/casual/parcels` (SPEC §3–5, `levels.json`); точки — stazzi `apps/casual/pairs`. История идей — `IDEA.md`, `IDEA-cave-in.md`.

## Правила

Поле — склад кубиков, прижатый ко дну. Кубик простой, с числом или с чёрной / белой точкой. Пальцем тянешь **рамку** от клетки до противоположного угла и отпускаешь. Рамка допустима, если в ней только кубики (без пустот) и это **одно из двух**:

- **посылка с числом** — ровно одно число, точек нет, площадь равна числу;
- **посылка-пара** — ровно одна чёрная и одна белая точка, чисел нет, размер любой.

Посылка уходит, в её столбцах всё, что выше, падает на высоту рамки; другие столбцы не двигаются. Цель — отправить все кубики. Тупик — кубики остались, а допустимой рамки нет: строка «застрял» с Restart. Отмены хода нет (решение автора stazzi).

## Цвета

Без горчичного (решение автора, 2026-11-19): простой кубик — светлый крафт, кубик с числом — синий с числом, точки — чернила и бумага (одинаково в Post и Night). Свои переменные `--pc-*` в `view.js`.

## Уровни (решение автора, 2026-11-19): 100, сначала цифры, потом пара входит в цифры

**Уровень 0** — учебный, в `view.js` (`tutorial`): рука показывает три хода, «2» падает после того, как ушла «4». **«?»** — живое мини-поле, рука сама играет три шага (`demo`).

| Уровни | Что | Поле |
|---|---|---|
| 1–8 | только цифры | 4×4 → 5×5 |
| 9–11 | цифры + одна пара; **9 учит пару** (`teach`: рука показывает первый ход — пару) | 4×4, 5×5 |
| 12–15 | цифры + две пары | 5×5 |
| 16–90 | смесь, ступени растут волной; вкус меняется: ровная смесь / мало пар / много пар / изредка только цифры | 5×5, 6×6 |
| 91–100 | финал на большом поле | 7×7 |

Уровней с одними точками нет: отдельный блок точек ощущался бы как другая игра (решение автора). Каждый уровень с точками приходит в письме только после уровня 9 (`needs`).

**Ступень** (1–6) — из двух мер вместе: число посылок и доля первых рамок, после которых уровень ещё решается (`good`); ступень = среднее, округлённое вверх. В письме: 1–2 лёгкий, 3–4 средний, 5–6 трудный. Сейчас 28 лёгких, 45 средних, 27 трудных. Уровень stazzi «2» (8 посылок, 0,50) по этой мере сам попадает в средние — как и решил автор.

**Откуда:** ступени 1–3 — случайный разрез поля на посылки; ступени 4–6 и 7×7 — **сборка от конца** (`tools/reverse.js`, идея автора): пустое поле, посылки вставляются по одной, в том числе под уже стоящие, поэтому падение — часть решения. Цифровые слоты со ступени 4 берут подходящие уровни stazzi. Общий паттерн — `games/GENERATOR.md`.

## Генератор — `tools/`

```
node games/parcels/tools/make-100.js k n     # воркер k из n: пишет tools/out/slot-N.json (не в git)
node games/parcels/tools/make-100.js write   # собирает levels.js
```

`solver.js` — быстрый солвер (суммы по прямоугольникам); на 30 уровнях stazzi даёт ту же сложность, что солвер stazzi. `test.js` прогоняет решения всех 100 уровней через движок.

## Открытые вопросы

- Мера сложности — пока «ловушки + размер»; по `games/GENERATOR.md` перейти на «сколько думать вперёд».
- Цифры и точки в одной посылке запрещены — проверить на плейтесте, что это понятно без отдельного урока.
- Ступень 6 случаем почти не выпадает; трудные — в основном ступень 5.
