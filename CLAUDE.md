# Postie — заметки для Claude

Сборник маленьких логических игр с ежедневной почтой от почтальона. **Название — Postie, в сторе «Postie — daily puzzles»** (решение автора, 2026-11-03). Репозиторий пока называется pocketpuzzle — не переименовываем без отдельного решения.

## Файлы

- `CONCEPT.md` — **концепция: только действующие решения** (что это, цикл дня, принципы, платформа, метрики, открытые вопросы, соцслой на потом).
- `design/STRUCTURE.md` — **структура по шагам:** три экрана (письмо, коллекция, календарь), навигация, первый запуск. Новые решения по экранам — сюда.
- `web/` — **плоский прототип всей логики** (Vercel, проект `postie`, https://postie-jade.vercel.app; корневой `vercel.json` собирает `web/` в `dist/`): `index.html`, логика дня — `web/js/main.js`, вид — `web/kit/flat.css`, кит игр — `web/kit/kit.js`, `kit.css`; порядок игр — `web/games.js`; `web/games` — ссылка на `games/`. «test» в углу: следующий день, решить 3, сброс.
- `games/` — **16 игр, 295 уровней**, у каждой папка `games/<игра>/` (levels.js, engine.js, view.js, icon.svg, test.js, README.md, IDEA.md; контракт — `games/README.md`). Проверка: `node tests/run.js` — решение каждого уровня прогоняется через движок.
- `WORLD.md` + `world/` — **мир:** ядро и видение автора, механика глазами мира, голос, табу; канон с ID (`timeline`, `places`, `people`, `postman`, `ciphers`, `notes`, `patterns`); черновик голоса писем — `world/letters-draft.md`. Одно письмо = один факт канона + один новый вопрос; противоречить канону нельзя.
- `TECH-UNITY.md` — техническая основа: Unity 6.3, iOS и Android, перенос игр из `games/` на C#, данные, платформа.
- `design/VISUAL.md` + `design/ref/v2/` — **визуал v2 (бумага, марки), отложен до арта, не отменён.**
- `RESEARCH.md` — исследования рынка и референсов (Almanac, отзывы, мета-слои, переписка с незнакомцами, философские опоры). Выводы, не решения.
- `archive/` — **всё старое**: прежние концепция, карта экранов, техоснова, мир v1, дизайн v1 (`archive/README.md`). Не действует; не опираться без просьбы автора.

## Действующие решения (подробно — `CONCEPT.md`, `design/STRUCTURE.md`)

- **В MVP — 12 игр** (какие — открыто; в `games/` 16).
- **Три экрана:** письмо (Today) ← → коллекция (Games), календарь (Letters); свайп, открывается на Today.
- **Каждый день — письмо почтальона и 10 новых уровней:** случайно 1–5 лёгких, 1–5 средних, 1–5 сложных (вместе 9) и 1 самый сложный. Уровни новые, независимо от того, решены ли вчерашние. **Уровни будет делать генератор**; сейчас 295 — на 29 дней.
- **Письмо:** Today — пустой экран, по центру письмо или «письма нет» → записка почтальона, открыта сразу → «Go to puzzles» → сетка 3×4 → после каждой задачи попап: до трёх — Next; с третьей — Next или Send letter; после десятой — только Send letter → конверт: игрок сам клеит 3 марки в любом порядке, можно вернуться к задачам → Send.
- **Марка** — за каждую решённую задачу письма: игра и номер уровня; лишние сгорают. **У марок должна быть логика, очень трудная для разгадки** — какая, автор думает.
- **Почтальон отвечает на марки:** первый день — знакомство, дальше развилки по вчерашнему письму (отправил ли, какие марки). Лучшего письма нет.
- **После отправки:** марок больше нет, второй раз не отправить; оставшиеся задачи — только через Games, письмо — только через календарь. **Не отправил — письмо пропало, дослать нельзя.**
- **Коллекция:** только пришедшие игры, только по играм; уровни нумеруются по порядку прихода (1, 2, 3…), тот же номер на марке. **Уровни попадают туда только после отправки письма** (не отправил — на следующий день).
- **Календарь:** настоящий месяц, сверху — сколько писем отправлено; **два состояния дня — отправил / не отправил**; отправленный — письмо и три марки; сегодня ведёт на Today; к уровням дня из календаря не перейти.
- **Визуал сейчас — максимально просто, без арта:** белый экран, плоские точки. Сначала механика игр и логика, потом арт.
- **Хук:** игрок не знает, что почтальон напишет завтра, и знает, что тот ответит на его марки.
- **Мир:** будущее; почтальон — сильный ИИ, оставшийся один, спрятанный спаситель, никогда не названный; игроки — сознания людей внутри Best Version; письма — его мысли, тяжёлые вопросы, неровные, непредсказуемые; мир без конца, слоёв-поворотов нет; компании — только прошлое мира. Подробно — `WORLD.md`.
- **Без давления:** нет таймеров, стриков, рекламы внутри решения; один палец, не больше трёх жестов (тап, перетаскивание, свайп).
- **Платформа:** Unity 6.3, нативные iOS и Android; английский в приложении; всё локально; Firebase; уведомления — после первой отправки; только светлая тема; покупок нет, монетизация позже.
- **Позже — соцслой:** письма незнакомцам только через почтальона, раз в день, ответ завтра, анонимно, письмо запечатано головоломкой.

## Правила работы

- **Пушить в `main` всегда** — после каждой правки, **только в `main`**; других веток не создавать (решение автора, 2026-11-02). Сначала `git fetch`, пушить только fast-forward; если `main` ушёл вперёд — сказать автору, не затирать.
- **Новое решение автора — сразу в `CONCEPT.md` / `design/STRUCTURE.md` и сюда; заменённое — убрать**, а не копить рядом «было / стало». Старый текст живёт в истории git и в `archive/`.
- **Не смотреть в репо `stasHrytsko/stazzi` и не применять его правила**, пока автор не скажет. Исключение — по прямой просьбе автора за конкретным материалом.
- Отвечать автору по-русски, коротко, по-человечески.
- Не выдумывать цифры: прогресс, число уровней, проценты, отзывы. Нет данных — плейсхолдер в квадратных скобках или «нужно проверить».
- Не превращать примеры в правила: открытые вопросы — в `CONCEPT.md` §8.
- Отделять решения автора от выводов исследований и от предложений Claude: **[решение]**, **[принято]**, **[открыто]**.
- После правки прототипа — прогнать `node tests/run.js` и проверить поток в браузере (Playwright).
